# BexLogs REST API

← [Documentation index](./README.md)

A read-only HTTP API over the bexlogs domain models, generated by
[API Platform for Laravel](https://api-platform.com/docs/laravel/) and gated
end-to-end by [Laravel Sanctum](https://laravel.com/docs/sanctum) personal
access tokens.

> **There is no anonymous access.** Every request — including the OpenAPI
> spec at `/api/docs` — requires either a logged-in session **or** a Bearer
> token. The query layer additionally scopes every read to the
> authenticated user's organizations, so a valid token can only see data
> the user could see in the UI.

## Base URL

```
<APP_URL>/api
```

For local dev that's typically `http://localhost:8000/api`. The currently
configured base URL is shown on the **Settings → API tokens** page along
with a copy-paste curl example.

## Authentication

The API authenticates requests with the `auth:sanctum` middleware, which
accepts:

1. A **Personal Access Token** in the `Authorization: Bearer <token>`
   header — for CLI/CI/SDK clients.
2. The session cookie of a logged-in operator — convenient for browsing
   the Swagger UI sandbox at `/api/docs` from a normal browser tab.

### Creating a token

1. Log into bexlogs and open **Settings → API tokens**
   (`/settings/api-tokens`).
2. Enter a descriptive name (e.g. `CI deploy script`, `metrics-pipeline`)
   and click **Create token**.
3. Copy the plaintext token shown in the modal. **This is the only time
   it will be displayed** — Sanctum stores only the SHA-256 hash. If you
   lose it, revoke it and mint a new one.

Tokens carry the single ability `read`. Writes are not exposed yet.

### Revoking a token

Click **Revoke** on the row in the active-tokens list. Revocation is
immediate — the next request using that token will get `401`.

### Rate limit

Each token (or session) is throttled to **60 requests / minute** by the
`throttle:60,1` middleware on the API route group. The standard
`X-RateLimit-*` headers are returned on every response.

## Example request

```bash
curl -H 'Accept: application/ld+json' \
     -H 'Authorization: Bearer YOUR_TOKEN' \
     http://localhost:8000/api/subscriptions
```

JSON-LD (`application/ld+json`) returns a paginated envelope:

```json
{
  "@context": "/api/contexts/Subscription",
  "@id": "/api/subscriptions",
  "@type": "Collection",
  "totalItems": 12,
  "member": [
    {
      "@id": "/api/subscriptions/abc123",
      "@type": "Subscription",
      "id": "abc123",
      "name": "Acme staging",
      "environment": "staging",
      "autoScrape": true,
      "scrapeIntervalMinutes": 5
    }
  ],
  "view": { "@id": "/api/subscriptions?page=1", "@type": "PartialCollectionView" }
}
```

Plain `application/json` returns a flat array of the same items without
the envelope — useful for one-off scripts that don't care about
`totalItems` / `view`.

## Pagination

Collection endpoints paginate by **30 items per page**. Pass `?page=N`
to walk the pages; the `view` block in the JSON-LD response carries
`first`, `next`, and `last` links so a client can follow them blindly.

`LogMessage` allows the client to override the page size up to 100 via
the `itemsPerPage` query parameter (it's the highest-volume resource —
30/page can be uncomfortably small for log diff tooling).

## Exposed resources

| Path                  | Resource       | Notes                                                                                             |
| --------------------- | -------------- | ------------------------------------------------------------------------------------------------- |
| `/api/organizations`  | `Organization` |                                                                                                   |
| `/api/applications`   | `Application`  |                                                                                                   |
| `/api/subscriptions`  | `Subscription` |                                                                                                   |
| `/api/scrape-jobs`    | `ScrapeJob`    |                                                                                                   |
| `/api/log-messages`   | `LogMessage`   | Largest table. Default 30/page, `itemsPerPage` configurable up to 100.                            |
| `/api/bex-sessions`   | `BexSession`   | **No cookie data ever serialised** — only id/environment/account/captured_at/last_validated_at/expired_at. |

All collections also expose a corresponding `/{id}` show endpoint.

## OpenAPI documentation

Browse the auto-generated, always-up-to-date Swagger UI at:

```
<APP_URL>/api/docs
```

You'll see a 401 if you hit it without auth. Either log into bexlogs in
the same browser tab first, or paste your token via the **Authorize**
button (the Personal Access Token scheme is preconfigured).

The machine-readable JSON OpenAPI document is at `/api/docs.jsonopenapi`
(also gated). Use it with any OpenAPI client generator.

## Scoping guarantee

A query through any exposed resource walks back to a `user_id` and
filters on the authenticated user. The single enforcement point is
`App\Api\QueryExtension\OrganizationScopeExtension`, which is tagged
into both API Platform's collection and item providers. If a future
`#[ApiResource]` is added without a matching scope rule, the extension
logs a `LogicException` and serves zero rows — fail-closed by design.

## Out of scope

- **Webhook delivery** — deferred. See `docs/future-features.md`.
- **Data export endpoints** (CSV/parquet) — deferred.
- **Write operations** (POST/PATCH/DELETE) — none exposed. Sanctum
  tokens have only the `read` ability today.
